# EVENTS — Event store — schema = CONTRACT

The harness typed event store is the unified, auditable view of the runtime:
typed per-session events in `.runecraft/events/<sessionId>.jsonl`
(append-only, one line = one event), an execution fingerprint (harness
bundles), gate-failure lessons and deterministic jsonl export. **This
document is the schema CONTRACT**: the layers that produce events conform to
the kinds WITHOUT replanning — each existing sink stays its own owner; the
observability layer observes and bridges read-only on export.

## 1. Line format (one event)

```
{"seq":0,"kind":"session:started","sessionId":"s1","bundle":"a7f3…(12 hex)",
 "prevHash":"<sha256 of the previous line; first line = sha256(\"\")>",
 "source":"internal|sdk|bridge","payload":{…,"at":"<ISO wall-clock>"}}
```

- **Identity** = `(seq, kind, sessionId, bundle, argsHash, triggerSignature)`
  — deterministic; **timestamps are never part of identities**. `at` (ISO
  wall-clock) exists only in the informational payload (excluded from
  determinism asserts — documented in the cases).
- **seq**: integer ≥ 0, monotonic per session (post-crash recovery continues
  from the last VALID seq in the file).
- **prevHash**: sha256 of the previous line (tamper-evident; violations are
  reported on export — exit 0 with a warning).
- **bundle**: short prefix (12 hex) of the session bundle. The full hash
  (64 hex) lives in the payload of the `session:started` header.
- **source**: `internal` (generated by the harness) · `sdk` (observed from
  the SDK) · `bridge` (materialized from an external sink on export — the
  harness reads, never rewrites).
- **runId**: optional (the v1 extension does not emit it — the OTel trace_id
  uses runId|sessionId; see section 5).

Best-effort writes (same pattern as the verification verdict recorder —
**never breaks the session**); kill switch `RUNECRAFT_OBSERVABILITY=0|false|off`
→ inert layer (zero files); fail-soft reads (malformed lines are skipped).

## 2. Kind catalog (v1)

| Kind | Payload (fields) | Emitted by |
| --- | --- | --- |
| `session:started` | bundleHash (64 hex, header), agentId, model, gitHead, versions{harness,sdk,forks}, at | observability (extension, session_start) |
| `session:ended` | durationMs, toolUsage[], delegations[], totalToolCalls, totalDelegations, agentId, model, tokenTotals, at | observability (agent_end / session_shutdown) |
| `bundle:changed` | bundleHash (new full), at | observability (config changes mid-session — old events immutable) |
| `context:usage` | usedTokens, maxTokens, usagePct, action (none\|warn\|recover), source (sdk\|bridge), at | observability (ctx.getContextUsage / taskflow token-budget) |
| `tokens:usage` | input, output, reasoning?, cacheRead, cacheWrite, totalMessages, at | observability (tool_result.usage / token-budget) |
| `tool:call` | tool, argsHash (normalized sha256 — NEVER raw args), at | observability (tool_call) |
| `tool:result` | tool, ok, blocked?, guardId?, reason?, durationMs, at | observability (tool_execution_end) |
| `delegation` | agent, toolCallId, durationMs, at | observability (subagent tool) |
| `guard:blocked` | guardId, tool, reason, at | observability (tool_execution_end + reason `<guardId>: msg`) |
| `verification:verdict` | verifyId, status, layer, reason, suggestion, cost, at | **bridge** (verify-verdicts.jsonl, owned by verification) |
| `resilience:signal` | signal, detail, at | **bridge** (goal-loop ledger + continuation.json + resilience-events.jsonl, owned by guards/resilience) |
| `lesson:captured` | lessonId, triggerSignature, trigger, antiPattern, preferred, priority, gate, track, count, at | observability (gate failure) |
| `lesson:reincidence` | lessonId, triggerSignature, count, at | observability (same trigger+gate) |
| `lesson:promoted` | lessonId, triggerSignature, priority, count, at | observability (threshold → promoted.jsonl) |
| `adendo:injected` | track, gate?, lessonIds[], textHash, at | observability (before_agent_start) |

### CONTRACT kinds (reserved — v1 does NOT emit)

| Kind | Contract |
| --- | --- |
| `verification:started` | verification may emit when the cascade starts directly in the store — no retrofit |
| `verification:stage` | verification may emit per executed stage — no retrofit |

## 3. Boundaries (each sink stays owner; no duplication)

| Sink | Owner | Observability |
| --- | --- | --- |
| `.runecraft/verify-verdicts.jsonl` | verification | Read-only bridge on export → `verification:verdict`; end-of-session sweep → lessons (fail/halt) |
| `.pi-glla/active.jsonl` (ledger) | guards/resilience | Read-only bridge on export → `resilience:signal` (pending_latch_stuck/wedge_alert/heartbeat_refire) |
| `.runecraft/continuation.json` | resilience | Read-only bridge → `resilience:signal` (continuation) |
| `.runecraft/resilience-events.jsonl` | resilience | Read-only bridge → `resilience:signal` (stall:* / fallback / continuation_*) |
| `evidence/` (evals) | evals | Untouched (eval-specific) |
| `.runecraft/events/` + `lessons.jsonl` + `lessons/promoted.jsonl` | observability | Exclusive writes |

Fine-grained `.gitignore`: `.runecraft/events/` and `.runecraft/lessons.jsonl`
are gitignored (runtime-derived data); `promoted.jsonl` is VERSIONED (team
memory; consumed by the memory layer).

## 4. Export (`harness events export --format jsonl [--session <id>] [--include-external]`)

- Ordering: (sessionId lexicographic, seq asc) — 2 runs → **byte-identical**.
- **Bridges** (--include-external): verify-verdicts.jsonl →
  `verification:verdict`; goal-loop ledger + continuation.json +
  resilience-events.jsonl → `resilience:signal` — all with `source:"bridge"`
  and a **virtual seq** (monotonic in the target session).
- **Session attribution of bridges**: with `--session <id>` → appended to the
  requested session (seq = last store seq + 1 + i) ONLY if the session has
  events in the store; without `--session` → synthetic session `__bridge__`
  (the external sinks are cwd-scoped, with no session attribution in the
  files — honest).
- **prevHash chain** verified → violations on stderr (exit 0 with warning).
- **Fail-soft**: malformed lines (store AND bridges) are skipped and counted.

## 5. OTel / Langfuse mapping (OTel implementation DEFERRED)

> **Dated note 2026-08-08:** the OTel/SDK export is DEFERRED in v1 (zero new
> dependencies locked). The contract below documents the future mapping; v1
> materializes deterministic jsonl only.

| Kind | OTel | Langfuse |
| --- | --- | --- |
| `session:started` | span `session` (trace_id = runId\|sessionId; attributes = payload) | trace start (id = sessionId) |
| `session:ended` | span `session` (end; durationMs) | trace end (usage = tokenTotals) |
| `bundle:changed` | span attribute update | observation `bundle` |
| `context:usage` | span `context` (attributes usedTokens/maxTokens/action) | observation `context` |
| `tokens:usage` | span `tokens` (attributes input/output/cache) | observation `tokens` |
| `tool:call` | span `tool.<name>` (attributes argsHash) | observation `tool.<name>` (input) |
| `tool:result` | span `tool.<name>` (end; ok/blocked/durationMs) | observation `tool.<name>` (output) |
| `delegation` | span `delegation` (attributes agent) | observation `delegation` |
| `guard:blocked` | span `guard` (attributes guardId/reason) | observation `guard:blocked` |
| `verification:verdict` | span `verification` (attributes status/layer) | observation `verification` |
| `resilience:signal` | span `resilience` (attributes signal/detail) | observation `resilience` |
| `lesson:captured/reincidence/promoted` | span `lesson` (attributes lessonId/gate) | observation `lesson` |
| `adendo:injected` | span `adendo` (attributes track/lessonIds) | observation `adendo` |

General rule: `trace_id = runId|sessionId`; `span = kind`; `attributes =
payload` (minus `at` — the span timestamp). Langfuse: `trace = session`,
`observation = kind`.

## 6. Honest limitations (validated at execution)

- **The `tool_call` result does NOT expose a guard block**: the SDK runner
  (runner.js `emitToolCall`) short-circuits at the first `{block:true}` —
  extensions registered after the guards (manifest order) do NOT receive the
  event. Blocked calls do NOT emit `tool_result` (agent-loop.js skips the
  afterToolCall for immediate results). **The REAL block observation is
  `tool_execution_end`** (isError + reason `<guardId>: msg` in
  result.content — `createErrorToolResult`): → `guard:blocked`.
- **`tool:call` of blocked calls is NOT recorded** (args unavailable at
  `tool_execution_end`) — the block appears as `tool:result` (blocked) +
  `guard:blocked`.
- **SDK `context` event = only messages** (no tokens): the context source is
  the typed API `ctx.getContextUsage()` (`ContextUsage {tokens, contextWindow,
  percent}`) + the taskflow token-budget (read-only bridge; NEVER writes into
  `.pi/`). `shouldCompact` (pure, SDK) stays as an on-demand check.
- **before_agent_start** fires per user prompt (not per internal turn): the
  execution addendum (lessons from the gate that failed) is injected at the
  next before_agent_start — chaining preserved (does NOT overwrite other
  extensions).
- **Lessons**: captured on HARD gate failures (guard block, verification halt
  via tool_execution_end; fail/halt from verify-verdicts.jsonl + resilience
  signals in the end-of-session sweep — deduped by triggerSignature); soft
  verdicts (skip) do not capture lessons in v1.
