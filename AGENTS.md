## Memory layer scoping (`packages/harness/src/memory/`)

- **Storage root is the MAIN checkout, not the current working tree.** `resolveMemoryDir`/`resolveProjectSlugSync` go through `resolveSharedGitRootSync` (`src/memory/project.ts`): `findGitRoot` stops at the first `.git`, which in a linked worktree is a `.git` FILE belonging to that worktree. Resolution: `.git` is a directory → the root itself (no extra git call); `.git` is a file and `gitDir == gitCommonDir` → `--show-toplevel` (submodule / `--separate-git-dir`); otherwise (`gitDir != gitCommonDir`) → the main worktree from `git worktree list --porcelain`, accepted only if `git rev-parse --show-toplevel` on it returns itself and it is not the git common dir — bare and `--separate-git-dir` mains make git report a git DIR there, and the memory root must never resolve into one (those worktrees keep their own dir). Don't "simplify" this back to `findGitRoot` (splits the DB per worktree) or to `dirname(--git-common-dir)` (gates F20's helper — it mis-resolves submodules and `--separate-git-dir`). Real worktree + submodule + bare-main + separate-git-dir proof: `test/memory/paths.test.ts`, `test/memory/project.test.ts`.
- **Project identity is collision-resistant without a migration.** `Repository.getOrCreateProject` keeps the historical base slug (last remote path segment) and only a remote whose base slug is already owned by a *different* remote gets `<slug>-<sha256(canonicalRemoteKey)[:8]>`; existing rows are never rewritten. One continuity tiebreaker precedes that: a row whose `root_path` is this repository root keeps the project across a remote rename/transfer (the accepted, documented cost is that a different repo cloned into the exact same path with the same trailing segment inherits it). Two roles in `src/memory/project.ts` must stay separate: `normalizeRemoteUrl` feeds the SLUG and is frozen (byte-compatible with released behavior — widening it renames existing projects and hides their memories); `canonicalRemoteKey` (`host/path`, scheme/user/port/trailing-`/`/`.git` ignored) is for `sameRemote` and the disambiguation hash only. A `null` remote never conflicts. Tests: `test/memory/repository.test.ts` (`getOrCreateProject`), `test/memory/project.test.ts` ("slug é CONGELADO").
- `Repository.getMemory`/`updateMemory`/`softDeleteMemory` take a `projectId` and `endSession` takes `(sessionId, projectId, summary?)` — all ID-based reads/mutations and session ops are bound to the calling project, matching the existing `findActiveSession`/search project-scoping model. A foreign id/session is refused as `NOT_FOUND` (never a distinct "exists elsewhere" signal). `saveMemory`'s optional `sessionId` is checked via `Repository.getSession(id, projectId)` and refused with a `SESSION_NOT_FOUND` `ValidationError` if it belongs to another project. See `docs/MEMORY.md` for the tool-contract wording and `test/memory/{repository,tools}.test.ts` for the cross-project regression tests.
